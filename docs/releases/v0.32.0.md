# VOXEL v0.32.0 — Ely.by no Launcher (e o card azul removido de vez)

**Not affiliated with Mojang Studios or Microsoft.**
VOXEL é uma plataforma de criação independente para Minecraft Java Edition.

---

## O que muda nesta release

### 1. O card azul flutuante saiu de vez

O pill azul no topo da janela era o *SkipLink* (atalho de acessibilidade "pular
para o conteúdo"). Ele foi **removido** — não escondido, removido: componente,
renderização, card da página `/accessibility` e texto traduzido. O landmark
`<main id="main-content">` continua único e correto; a ordem de foco segue
natural (sidebar → conteúdo).

### 2. Ely.by became um provider de autenticação de verdade

O Launcher agora autentica por **Microsoft** ou por **Ely.by** — a escolha é
sua, em **Settings → Launcher**.

- **Device flow oficial Ely.by (RFC 8628)**: o app pede um código curto, você
  aprova no navegador em `https://account.ely.by/code`. **A senha nunca é
  pedida, nunca é gravada e nunca sai do seu PC.**
- **Public client**: sem *client secret*. Só o `client_id` é necessário.
- **Escopos pedidos**: `account_info offline_access minecraft_server_session`
  (o último é o que habilita a sessão de servidor Minecraft).
- **Lançamento com `authlib-injector`**: para a conta Ely.by, o Minecraft Java
  é iniciado com o `authlib-injector v1.2.8` (baixado do release oficial e
  conferido por **SHA-256** antes de rodar) e a sessão passa pelo
  `ely.by`. A conta Microsoft continua usando o caminho `msa` de sempre.

### 3. As duas contas convivem

Microsoft e Ely.by têm **namespaces separados** no keyring (`mc_*` e `ely_*`).
Trocar a conta ativa **não apaga** a outra: você pode alternar entre elas
quantas vezes quiser. O *sign-out* de um provider revoga o refresh token
remotamente (quando possível), **sempre** limpa as credenciais locais e devolve
a seleção para o outro provider se ele existir.

### 4. Endurecimento do fluxo OAuth

- Timeout **total** por requisição — cobrindo a leitura do corpo HTTP, não
  só a conexão.
- Cancelamento e timeout derrubam requisição, corpo e *polling*.
- Redirecionamentos bloqueados.
- O `plugin-http` só pode falar com os **4 endpoints oficiais** do Ely.by
  (`devicecode`, `token`, `revoke`, `minecraft/profile`).
- `open_auth_url` só abre `https://account.ely.by/code` e
  `https://account.ely.by/dev/applications/new` (host, porta e caminho exatos).
- O *polling* respeita a expiração do device code e obedece `slow_down`.
- Refresh valida a identidade da sessão antes de gravar — um refresh atrasado
  nunca sobrescreve um login mais novo.
- Escrita parcial e **cancelamento durante os writes finais** rechem tudo:
  credenciais apagadas e a conta anterior restaurada.

## Como usar o Ely.by

1. Crie o aplicativo em <https://account.ely.by/dev/applications/new>
   (*Desktop Application*, **public client** — sem secret).
2. Copie o `client_id` para **Settings → Launcher → Ely.by**.
3. **Sign in with Ely.by**: abra o código, aprove no navegador.
4. Escolha a conta ativa (Microsoft ou Ely.by) e lance o Minecraft pelo
   workspace.

> Sem `client_id` o botão Ely.by fica desabilitado com a explicação — nada é
> inventado, nada é fingido.

## Limitações honestas

- O `client_id` do aplicativo público do VOXEL é **do dono** — ele é
  configurável em Settings → Launcher e não é distribuído com segredos.
- O device flow Ely.by depende da aprovação da conta no site do Ely.by; sem
  essa aprovação o login não se completa (e o app diz isso, sem simular
  sucesso).
